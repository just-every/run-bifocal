# Original LookML dashboard intake

Open `/app/import` as the current native owner and expand **Import original LookML dashboards**. Import and review the source snapshot first, then separately review and publish its native semantic model. This bounded intake creates editable inactive dashboard documents in the migration workspace. It never imports authority, publishes dashboards, executes original code, fetches connections or transfers schedules.

Supply up to eight original `.dashboard.lookml` files, each at most 32 KiB. Originals retain their filenames, exact text and digests. Each YAML document is a list of named dashboards. Duplicate keys, aliases, executable tags and excessive nesting are refused. Stable dashboard names and element names retain their identities through source deltas.

The mapping form accepts a JSON object. Each key joins the original model name and Explore name with a dot. Its value contains `modelId`, the exact published `revision`, `viewId`, `dataset`, exact `sourceRevision` and a `fields` map. Field mappings connect original qualified field names to physical native dimensions or native measure identifiers. The server checks the current owner, exact model revision, current dataset revision and existing view restrictions again at preview time. A mapping supplies no additional source rights.

Supported dashboards contain two to four `looker_grid` elements with `layout: newspaper`. Explicit `row`, `col`, `width` and `height` place tables in the source 24-column grid; even columns and widths map exactly to the native 12-column desktop grid. Overlap and out-of-bounds placements are refused. Phone drafts stack in source order and can be edited independently.

Each element supplies `model`, `explore`, `fields`, `filters`, `sorts` and an explicit `limit` between 1 and 5000. Supported measures are mapped physical SUM and count-distinct measures. Tables support up to four physical grouping fields, without null grouping values or non-ASCII text collation, and their explicit ascending sorts, for example `sorts: [orders.region asc]`. Scalar tables use `sorts: []`. Other ordering or collation semantics remain unsupported. Row limits are checked against the complete native result; a result exceeding the source limit is refused without truncation.

Filters are literal physical equality only. A text filter uses a quoted Looker string inside the YAML value, for example `orders.region: '"West"'`. Plain exact decimal values and boolean `yes` or `no` values are supported on matching physical types. Relative date expressions, dynamic filters, wildcard searches and calculations remain blocking gaps. Current native view filters and row restrictions remain in force.

Review the exact import fingerprint and Apply the inactive project. Review its native preview to see each independently enumerated element, dependencies, typed values, nulls and totals. Unsupported properties retain their source expressions, locations and remediation and block the affected dashboard. Review again after editing the native title or placements. Query changes require separately reviewed source mappings; the native editor cannot silently remove an original source obligation.

Undo uses the shared import door and refuses later native edits. Eligible project or linked-source erasure withdraws originals, drafts and edit history and prevents replay. Legal holds and minimum retention still apply, including to pending reviews. Original file custody continues after Undo until eligible erasure.

The supported source syntax is pinned to Google's [LookML dashboard parameters](https://docs.cloud.google.com/looker/docs/reference/param-lookml-dashboard) and [table-element parameters](https://docs.cloud.google.com/looker/docs/reference/param-lookml-dashboard-table-chart), with the retrieved document digests in the reader. Self-authored documented specimens establish bounded parser and native-preview behavior. They establish no real Looker estate qualification, provider output parity, permission transfer, scheduled delivery or migration cutover. Those requirements remain open under BIF-025 and its receiving clauses.

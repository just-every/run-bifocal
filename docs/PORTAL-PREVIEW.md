# Native tenant previews

BIF-020 and BIF-056 have an owner-only HTTP foundation. This is not a shipped customer portal. External customer access stays disabled pending reviewed policy. There are no portal screens, public grants, custom domains, SDK, React components, signed iframe entry, billing, SSO mapping or automatic delivery in this cut.

Use the native signed-in installation owner session and the installation origin on every request. A preview token adds scope; it never replaces that session. All responses prohibit caching and referrer disclosure. Public marketing URLs grant no access.

The tenant collection is at `/api/operator/portal/tenants`. POST an empty JSON object to provision an inactive tenant; GET lists the owner's current tenants. Each following action is beneath that tenant's id.

1. POST `review` with `document`. The document has `schema: 1`, `sdk: 1`, a display name, a hexadecimal color, an exact published native `modelId`, `revision` and `viewId`, nonempty equality `rows`, explicitly permitted `dimensions`, and positive query and export budgets. Only a single-source view is supported. The preview intersects the model's immutable rules with the tenant's rows before aggregation. It shows exact scoped results and a review digest.
2. POST `stages` with that exact document and `reviewedDigest`. This saves an immutable release without changing the current publication. Its response identifies the release, the current generation and a separate activation digest. GET a `releases` path followed by its version to review an earlier release for explicit rollback. Unsupported schemas and SDK versions are refused.
3. POST `activate` with `version`, `previousGeneration` and the activation `reviewedDigest`. Publication and rollback require current model and source fingerprints. Each changes the generation and withdraws earlier tokens, cached results and unfinished jobs. Nothing activates automatically.
4. POST `tokens` with the installation origin as `audience`, an `action` of `read`, `export` or `queue`, and `ttlSeconds` between 1 and 300. Keep the returned token private. It is server-signed, owner-bound, tenant-bound, audience-bound, action-bound, generation-bound and single-use. Send it as a Bearer authorization header on the matching POST action. Tokens are never accepted in URLs.
5. Reads and JSON exports accept only `groupBy` and equality `filters` on explicitly granted dimensions. Neither can change the source, model, measures or fixed tenant rules. Results expose scoped aggregate rows and matching-row counts, without global input counts, hidden source metadata or raw source records. Caches are partitioned by tenant, generation and normalized parameters, with current source and model checks before every response.
6. `queue` stores only the requested export parameters. A POST to a `jobs` path followed by its id and `run` explicitly processes that export under a fresh export token. It never sends mail or invokes a delivery provider. Admission reserves a tenant-specific export unit. Processing that admitted job does not charge a second unit; a failed attempt retains its reserved unit. Queries reserve a unit before analytical execution, including cached reads. Budgets are cumulative and survive rotation and publication. GET `usage` shows the counts; provider cost is explicitly unavailable.
7. POST `suspend` or `rotate` with `previousGeneration`. Suspension, token withdrawal, cached-result removal and cancellation of queued or processing exports commit atomically. Final response guards also reject a request whose session, tenant generation, source or model changed during computation. Another tenant's counters and releases are independent.
8. GET `archive` exports this tenant's definitions and preview history. POST `erase` with `previousGeneration` and `confirmTenant` equal to this tenant's id to retire it and delete its releases, tokens, caches, jobs and usage. Minimal action audit and a tombstone remain. Shared source rows and independent reports are not tenant-owned storage and are not erased by this preview action; complete tenant erasure remains unproved.

Installation archives retain definitions, usage and action history, while excluding live activation, tokens, cached results and jobs. Restored definitions require fresh owner review and activation. Source changes and model or owner authority changes permanently withdraw local activation; restoring an earlier source or model does not revive it. Each queued export retains its exact release version. Source erasure removes retained releases and parameter sets derived from that source, including cancelled historical jobs, while preserving current releases and queued exports of other sources and their reserved usage. No external copy, legal retention, provider deletion, schedule, add-in or host integration is qualified by these native preview routes.

The public-door assertions are in `tests/journeys/portal-tenants.mjs`, invoked by the existing content-governance journey in push Verify. The focused local entry uses `BIFOCAL_FOCUS=portal`; the ordinary journey runs it without that flag. No new browser screen or permanent test registration is introduced.

The emitted-Worker scheduler in `tests/journeys/machine-boundary-worker.mjs` inserts a real authenticated suspension immediately before an export response transaction. The export has already computed, but its final current-access guards refuse the response. The existing optional CLI archive journey also proves retained preview definitions and usage without activation, tokens, caches or jobs; fresh owner review is required before a new scoped read. This bounded proof does not establish scheduled delivery or complete business-data restore.

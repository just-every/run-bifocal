# Bounded web snapshots

The owner can open **Files → Read a web source**, configure an endpoint and an explicit scalar column mapping, authorize one read, then review the resulting plan in the shared import door. Apply, reconciliation, retained versions, normalized CSV download, Undo and reviewed erasure use the same owner-only file workflow. This is a manual complete snapshot, not a scheduled connector or incremental synchronization job.

The installation administrator sets `BIFOCAL_WEB_SOURCE_ORIGINS` to a comma-separated list of approved public HTTPS origins. An empty setting permits no requests. Each read starts from an endpoint on that list; all continuations must retain its exact origin. IP literals, local destinations, embedded credentials, secret query parameters and all redirects are refused. Only GET is sent. The submitted OAuth bearer token stays in memory for that read; no native cookie is forwarded and no token or raw provider error is retained in diagnostics or consent history. There is no OAuth authorization grant, token refresh or stored credential facility in this bounded door.

JSON mappings use explicit dotted property paths. Scalars become the declared text, number, money, date or boolean column; null, empty text, false and zero remain distinct. Decimal values should be strings to avoid floating point loss. XML accepts inert direct row elements and scalar child elements, including explicit XML Schema nil values. DTDs, entity declarations, processing instructions other than the XML declaration, inclusion elements and excessive nesting are refused. Nothing in source content is evaluated, rendered as HTML or fetched.

Pagination supports a JSON next-link field, HTTP Link next relation, explicit page and offset parameters, or a JSON cursor. Page and offset reads start at the first page, request the configured page size and terminate on a short page. Cursor reads start without a saved cursor and require an absent or empty next cursor to terminate. A repeated URL, invalid continuation, failed page, 429, expired grant, cancellation, schema mismatch, byte or row or time limit prevents a successful plan. No page is published independently. Bounds are 20 pages, 2,000 rows, 512 KiB of response bytes and 30 seconds. Cancellation records a native flag checked before and after every page; the current network request remains bounded by the read timeout.

OData reads the `value` collection and opaque next links. A final delta link is detected as inactive metadata and is never followed. Actual delta responses with removed entities are refused. Durable delta cursors, backfill, overlap reconciliation and an outbound ODBC or JDBC agent are not implemented. Full snapshots explicitly disclose the absence of an incremental deletion or history feed. The owner approves that policy and separately approves the exact replacement plan, including absent rows. An empty complete snapshot is reviewable and can replace current data; Undo restores the prior version.

Only normalized snapshot CSV and sanitized origin, format, page count and reconciliation metadata enter import custody. Upstream response documents and continuation URLs are not archived. The owner-only original download therefore returns the normalized CSV, not a claimed original API response. Erasure withdraws that snapshot with the rest of its import namespace. Consent history retains only the read id, dataset id, accountable owner, configuration fingerprint, timestamps and terminal state.

The network edge fixtures used by `tests/journeys/analytics-boundaries.mjs` through `proveWebSources` are synthetic responses at the real emitted Worker's outbound HTTP boundary. They follow these published formats:

- [GitHub REST pagination](https://docs.github.com/en/rest/using-the-rest-api/using-pagination-in-the-rest-api): HTTP Link relations and omission of the next relation on the final page.
- [OASIS OData JSON Format 4.01](https://docs.oasis-open.org/odata/odata-json-format/v4.01/odata-json-format-v4.01.html): value collections, nested complex properties, next links, delta links, and decimal strings with IEEE754Compatible.
- [OASIS OData Protocol 4.01](https://docs.oasis-open.org/odata/odata/v4.01/odata-v4.01-part1-protocol.html): finite server-driven collection paging and inactive delta links.
- [RFC 6750](https://www.rfc-editor.org/rfc/rfc6750.html): bearer Authorization and invalid-token refusal.
- [RFC 6585](https://www.rfc-editor.org/rfc/rfc6585.html): 429 rate-limit refusal with Retry-After.
- [W3C XML 1.0](https://www.w3.org/TR/xml/): inert element and entity syntax; this reader deliberately refuses DTDs and external entities rather than resolving them.

Generic page, offset and cursor parameter names are explicit operator configuration over those JSON response shapes; they do not certify a named provider adapter. These fixtures establish native HTTP behavior only, not a live provider grant, OAuth refresh, durable synchronization or driver operation.

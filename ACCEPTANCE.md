# Acceptance requirements

Target edition: 20 October 2026. This checklist covers the complete CONTRACT.md destination. Clause IDs are stable and mirror its Status table: **69 missing, zero done or partial, zero published**. There is no Bifocal implementation evidence yet. These journeys are future build requirements, not proof of release. Provider and platform enrollment, agreements and native distribution remain engineering obligations.

Use the real built public UI/API/CLI, Base owner lifecycle, native apps and spreadsheet hosts. Browser journeys run at 1440 and 390 CSS pixels with realistic US records, USD, current row/column grants and loading/empty/error/recovery states; inspect each persisted and delivered end state. Fakes are allowed only at paid/network edges from official versioned provider schemas. Distinguish sandbox, local and hosted evidence; a schema fake never establishes a live provider integration or agreement. Keep credentials out of artifacts. Performance targets require measured datasets/compute/network/cache state, while numerical correctness uses independently written reference queries.

## Shape validation before publication

The requested pre-repository status line retains literal `<full sha>`. Fresh Base's parser accepts only a hexadecimal commit identifier, so an unchanged no-repository draft cannot pass that one field. On delivery, replace it with the real main SHA and run the unmodified parser. A temporary validation copy may replace only that placeholder with the fresh Base checkout SHA to validate all clause rows/counts/grouping; this is explicitly structural validation, not a claim of a Bifocal judged commit. The final task report records the actual results and whether a repository was found.

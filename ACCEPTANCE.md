# Acceptance requirements

Target edition: 20 October 2026; buyer review 1. All 85 BI clauses remain missing: 78 target and seven push-further, with zero published clauses. This checklist mirrors CONTRACT.md exactly and makes no implementation or achieved-quality claim. Base foundation exists, but the BI journeys below are future requirements. Keep the original 30 desk IDs and all later clauses; unsupported source behavior remains a named gap until resolved, not successful migration.

Use real public routes, APIs, supported CLI commands, native devices and add-in hosts, with realistic US records and USD. Browser journeys run at 1440 and 390 CSS pixels and inspect persisted output and permission, empty, failure and recovery states. Use provider sandboxes or official-schema fakes only at the paid or network edge; disclose which is used. A fake never establishes live provider acceptance, app publication, agreement or licence. New import journeys use `/app/import`, its reviewed plan, reconciliation, apply and Undo. Every new record, artifact and derivative inherits scoped authority, audit, archive, erasure and sensitivity controls. Standing subscriptions follow BIF-053; every agent narrative requires instance approval. Sealed evaluation and cost measurements follow BIF-085; no permanent application tests are added by this document revision.
